# V6.3 内容与结构建议：从「板块清单」升级为「学科主线」

现状盘点（已核对 `src/lib/sections.ts`）：56 个 section 全部挂在扁平路由 `/s/:id`，靠 9 个一级域（NAV_GROUPS）分组；十大学科已各有「导读 + 实验室」，但仍存在四类结构问题。下面按优先级给出建议，你可以整包做，也可以只挑其中几条。

## 一、命名与信息层级清理（成本最低、收益最直接）

1. **版本号从用户可见文案里去掉。** 目前 `fixed-income-lab`、`macro-lab`、`behavior-microstructure` 的副标题以「V4.5 ·」「V4.6 ·」「V4.7 ·」开头，把内部迭代节奏暴露成了内容标签。改成能力描述（例：「信用与 OAS：Merton、CDS 反推、Ho-Lee 可赎回债」），版本信息只留在更新日志与 VersionBadge。
2. **实验室层级统一为三级命名法**：`基础工具` / `进阶实验室` / `前沿实验室`。现在固收有 4 个并列页（bond、rate-model、fixed-income-lab、fixed-income-frontier），用户无法从标题判断该先进哪个。
3. **拆分 `behavior-microstructure` 合并页。** 它同时覆盖行为金融与微观结构，而这两科各自已有独立的 lab + theory 页，三份内容互相重叠。建议把它的面板并入 `behavior-lab` 与 `microstructure-lab`，路由保留做 301 式重定向。

## 二、新增「学科主页」（Domain Hub）

为九个一级域各建一个 `/d/:groupId` 主页，取代目前只能在下拉菜单里看到的分组。每页包含：

```text
学科主页 = 一句话定位
         + 学习顺序（导读 → 基础 → 进阶 → 前沿，带完成度）
         + 该域核心公式速查卡
         + 该域可用的真实数据源入口
         + 相关长文与外部文献
```

这样首页只需要展示 9 张卡片而不是 56 个条目，路径从「找页面」变成「走主线」。

## 三、内容缺口（按学科补齐）

- **微观经济学**：唯一没有导读页的核心学科，建议补 `/s/micro-theory`（偏好与效用 → 生产与成本 → 市场结构 → 博弈与信息 → 机制设计）。
- **量化策略**：`quant`/`backtest`/`calibration` 三页缺一篇统领导读，建议补 `/s/quant-theory`（信号构建 → 组合构建 → 交易成本 → 回测偏误清单 → 实盘落差）。
- **公司金融**：全站空白，且与固收信用、资产定价天然衔接（资本结构、WACC、并购估值、股利政策）。
- **机器学习在金融中的应用**：目前只有 AI 长文，缺可复现工具（正则化因子选择、随机森林/梯度提升的因子重要性、交叉验证陷阱、Lopez de Prado 的组合清洗 CV）。
- **前沿长文**：现在只有 2 篇，建议固定为每次版本更新配 1 篇，形成可持续的「精读」栏目。

## 四、跨页连接（把 56 个页面织成网）

1. **概念反查**：术语表 `glossary` 里的每个词条自动列出「哪些工具用到它」，与「哪篇导读讲它」。
2. **前置知识链**：给每个 section 声明 `prereq: string[]`，在页面顶部渲染「建议先看」，并可由此生成一张全站依赖图。
3. **导读 ↔ 实验室双向链**：现在导读单向跳实验室，实验室面板缺回链到对应理论段落（可用锚点 `#part-3`）。
4. **统一符号表**：各模块对同一符号写法不一（σ、vol、波动率）。建一份 `src/data/notation.ts` 作为唯一口径，导读与工具共用。

## 五、每个工具页的固定结构模板

目前各实验室面板结构自由度过大。建议统一为五段式：**它回答什么问题 → 参数 → 图 → 怎么读这张图 → 常见误用**。「怎么读」和「常见误用」是当前普遍缺失的部分，也是把工具从「能算」变成「能教」的关键。

## 技术说明

- 学科主页复用 `NAV_GROUPS`，新增 `src/pages/DomainPage.tsx` + 路由 `/d/:groupId`，不改 `SECTIONS` 的数据形状。
- `SectionDef` 增加可选字段 `level`（basic/advanced/frontier）与 `prereq`，旧数据不填则不渲染，向后兼容。
- 合并 `behavior-microstructure` 时保留旧路由并在 `App.tsx` 做 `<Navigate replace>`，避免已发布链接与 sitemap 失效。
- 新增页面需同步 `sections.ts`、`zh.json`/`en.json`、`seoCopy.ts`（`check-copy-consistency.ts` 会校验），并跑 `generate-sitemap.ts`。

## 建议的落地顺序

先做第一部分（命名清理）与第四部分第 3 条（双向链），这两项不新增页面即可显著改善可用性；再做学科主页；最后按学科逐个补内容缺口，每个缺口一版。
