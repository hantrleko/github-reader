# Architecture rules
- Use Rollup's automatic dependency chunking rather than forced vendor groups; this avoids React/CommonJS initialization cycles while retaining dynamic-import route splitting.
- TradingView screener cache keys hash the request method, query and POST body in a versioned namespace; only identical public queries may share results.
- Keep uploaded introduction videos as Lovable Assets pointers, selecting one source by viewport orientation to avoid downloading both.
- Coordinate the global newcomer introduction with the homepage splash through explicit open/close events so dialogs never compete.
- Store automatic splash visibility per browser session; explicit replay remains available and automatic playback respects reduced motion.
- Keep the three-lab teaching path (routes, default scenarios, scenario-specific check answers) in one pure module shared by the homepage questions and each lab, so links, defaults and copy cannot drift apart.
- The desktop nav shows only the group menus that fit beside the right-hand controls (measured from an invisible copy) and sends the rest to the menu button, so long translated labels never cover the language switch.
- Floating page controls (`data-float`) use one global hit-test rule: they hide over any text, interactive, media or chart content and over `data-float-avoid` blocks, stay focusable while hidden, and show again on empty space; never add per-component lists or page padding for them.
- Intro films must degrade to a text fallback (unsupported format, load error, stall) and never block entry; the splash reel is decorative and is dropped when it cannot play.
- Baseline-vs-current comparison for the teaching-path labs lives in one pure module (`src/lib/baselineCompare.ts`) fed only by each lab's existing outputs; percentage results differ in percentage points, others absolutely, missing stays missing, and any teaching-path Reset clears the baseline through the shared path-reset event, so all three labs follow one rule.
- Service-worker navigations are network-only with the precached shell as the offline fallback (no NavigationRoute, no directory-index precache match), and the app never reloads itself: new builds are detected by comparing the running build id with the server's index.html meta and offered through a user-clicked refresh prompt, because a silent reload drops lab inputs and pinned baselines.
- Lazy pages and tools use `retryableLazy` (src/lib/lazyLoad.ts) under SectionErrorBoundary, which tells offline from failed download and re-arms failed imports only on a user Retry; Suspense fallbacks must show visible loading text, never hang or auto-retry.
- Baseline-comparison explanations come from one pure module (`src/lib/baselineExplain.ts`) that reads only the pinned/current inputs and the rows `compareRow` already built, returning i18n messages: no baseline → none, multi-input changes get joint wording only, seed/n changes are sampling variation, and missing stays "no result", so the three labs can never invent numbers or causal stories.
